# Lessons: writing specs and plans

- Status: Living (2026-11-27)

- **specs-1.** A §8 check written as "finds nothing" names the paths it covers. *Why:* `git grep 'design/m[0-9]'` also matched historical records that quote the old paths on purpose, so the check could never pass as written (rust-engine-experiment M3.15). *From:* rust-engine-experiment M3.15 · *Confirmed:* 2026-11-15
- **specs-2.** Evidence that §8 says will be "noted in `log.md`" is its own plan step, or it is forgotten. *Why:* M3.15's R7 follow-up note was missing until the spec review asked for it. *From:* rust-engine-experiment M3.15 · *Confirmed:* 2026-11-15
- **specs-3.** When a spec asks for a test per row of a table (every panic of §4.x, every operation), the plan names one test per row. *Why:* M3.17's plan named the panic tests loosely, and four of §4.5's rows (`ensure_capacity`, both `Extend`s, `From<[usize; N]>`) shipped untested until review. *From:* rust-engine-experiment M3.17 · *Confirmed:* 2026-11-16
- **specs-4.** Evidence recorded in `log.md` names the commit it ran on; a library or measured-code change after it (a review fix, a simplify pass) means re-running it or saying in the pull request that it predates the change. Write the hash in the same `log.md` entry, run after the commit; an entry promising "the hash is added later" never gets it. *Why:* M3.17's fuzz, wasm, full `ci` and `bench-regress` entries predated three later library commits, and the spec review could not tell which code they covered; in the engine's M3.6 the simplify pass and two review rounds changed measured spike code after the allocation counts were taken, so they were re-run on the final code; in M0.1 two entries left the hash for later and never got it. *From:* rust-engine-experiment M3.17, M3.6; M0.1 · *Confirmed:* 2026-11-27
- **specs-5.** A log line or caveat that names the cause of a measured gap says how the cause is known (measured by a variant, read from the assembly, or expected and unmeasured), and one that blames the spec's design cites the spec text that requires the work. *Why:* in the engine's M3.6 the log first stated two causes as fact that only one variant had measured, and charged a cost to a spec requirement when part of it came from a stricter check the spec did not ask for, which a later decision chunk would have read as a cost of the design. *From:* rust-engine-experiment M3.6 · *Confirmed:* 2026-11-27
- **specs-6.** A spec sentence that describes how existing code works is checked against that code in the grill; when a later step finds it wrong, the spec is amended in the same chunk, not only noted in `log.md` or the plan. *Why:* the engine's M3.25 spec described a join over the whole index space where the code skips empty regions; noted only in the log and plan, the Accepted spec contradicted the README until two documentation reviews asked for the amendment. *From:* rust-engine-experiment M3.25 · *Confirmed:* 2026-11-27
