# Lessons: xtask commands

- Status: Living (2026-11-27)

- **xtask-1.** A command that reads the repository tree finds the root itself (`git rev-parse --show-toplevel`) and runs git and reads files from there. *Why:* `cargo xtask` keeps the caller's current directory, so `check-docs` run from `xtask/` reported 21 false problems, telling the reader to add READMEs that existed (rust-engine-experiment M3.16). *Retire when:* every tree-reading command shares one root helper. *From:* rust-engine-experiment M3.16 · *Confirmed:* 2026-11-15
- **xtask-2.** Test a check that parses text files against a CRLF copy of the tree (clone into the scratchpad, convert every tracked text file, run the check and its tests there). *Why:* Windows checkouts with `core.autocrlf` give CRLF files and `.gitattributes` pins only scripts; the M3.16 portability review found `check-docs` correct this way in minutes (rust-engine-experiment M3.16). *From:* rust-engine-experiment M3.16 · *Confirmed:* 2026-11-15
- **xtask-3.** A loop that waits on a channel until a deadline checks `Instant::now()` against the deadline itself before each `recv_timeout`, and is tested with a producer that never stops, not only one that never sends. *Why:* `recv_timeout` returns a queued message before it looks at the deadline, so a guest printing without pause kept `doctor` past its 60 s deadline and wrote 507 MB of log in 10 s; the existing test used a silent reader. *From:* M0.1 · *Confirmed:* 2026-11-27
- **xtask-4.** To read a child's stdout and stderr as one stream, give both slots the same `std::io::pipe()` writer (`try_clone` for one) and drop the `Command` before reading, so the only write ends left are the child's. *Why:* a `Command` still holding a writer keeps the pipe open, and the reader never sees end of input when the child exits. *From:* M0.1 · *Confirmed:* 2026-11-27
- **xtask-5.** Choose processes to kill by pid only (`pgrep -f <tag>`, no `-l`), then re-check each pid on its own (`ps -o comm= -p`, `ps -ww -o args= -p`); never parse a process listing line by line, and in tests check a child's own pid with `kill -0`, not a pattern. *Why:* `pgrep -l` prints arguments unescaped, so a process with a newline in its arguments forged a line naming any pid; on Linux `-l` prints a 15-character name and `ps` takes its width from an exported `COLUMNS`; a test checking "no process left" with `pgrep -f "sleep 31"` was flaky. On macOS `comm` follows a rewritten `argv[0]`, so the re-check is only a check a process can fake about itself. *From:* M0.1 · *Confirmed:* 2026-11-27
- **xtask-6.** A test must reach the branch it names: give a parser at least one input where a naive parse (the first number) and the specified one disagree, give each prerequisite its own state in which only it is missing, and test a fixed list (such as an order of checks) by running its entries, not by comparing labels kept beside them. Check each new test against one plausible mutation of the code. *Why:* in `doctor`, every real version fixture started with its version, the prerequisite test failed at the first prerequisite, and the order test compared names, so each passed against broken code until review. *From:* M0.1 · *Confirmed:* 2026-11-27
- **xtask-7.** A check that dependencies stay inside `Cargo.lock` (a spike's, a stub's) compares the package list `cargo tree --offline --target all --prefix none --format '{p}'` prints against the lock, after pinning direct dependencies with `=` and copying the lock in. Do not rely on cargo's progress messages or on host-only resolution. *Why:* in M0.2's grill stub, `=` pins alone let transitive dependencies float in the shared cache; a lock alone let `syn = "2"` add a version outside it; cargo reported that as `Downgrading`, not `Adding`; and a crate under `cfg(target_os = "none")` was missing from the host tree (security and code reviews, checked in scratch stubs). *From:* M0.2 · *Confirmed:* 2026-11-27
